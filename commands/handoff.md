## Context

- Current branch: !`git branch --show-current 2>/dev/null || echo "(not a git repo)"`
- Git status (short): !`git status --short 2>/dev/null | head -30`
- Recent commits: !`git log --oneline -10 2>/dev/null`
- Uncommitted diff (stat): !`git diff --stat HEAD 2>/dev/null | head -40`

## Your task

現在のセッションでの作業を分析し、**次セッションの最初のメッセージとしてそのまま貼り付けられる引き継ぎプロンプト**を生成してください。目的はコンテキストの圧縮 — 新しいセッションの Claude が、この 1 通を読むだけで迷わず作業を再開できる状態にすることです。

フォーカス指示（任意、ユーザー引数）: $ARGUMENTS

### 手順

1. **セッションの棚卸し**
   - 今セッションで何を依頼され、何を行ったかを時系列で整理する
   - 変更・新規作成したファイル、採用した方針／棄却した方針を特定する
   - 上記 Context の git 状態（ブランチ・未コミット変更・直近コミット）を取り込む
   - 引き継ぎに有用な既存ドキュメントがあれば Read して要点だけ反映する:
     - `ROADMAP.md` / `PLAN.md` / `TODO.md` 等（未対応タスク）
     - `improvement_list/` の最新ファイル（直近の改修履歴）
     - プロジェクトの memory（`~/.claude/projects/{slug}/memory/MEMORY.md` の非自明な知見）
   - 引数でフォーカスが指定されていれば、その観点を最優先で詳述し、無関係な詳細は削る

2. **引き継ぎプロンプトの作成**
   以下の構成で、簡潔かつ自己完結した内容にする。各項目は事実ベースで書き、推測には「（推測）」と明示する。該当のない項目は省略してよい。

   - **タスク概要**: このセッションのゴールを 1〜2 行
   - **現在地**: 直近で何をしていたか（中断地点）
   - **完了済み**: 終わったこと（箇条書き）
   - **残タスク / 次の一手**: 次セッションが最初に実行すべきアクションを、実行可能な粒度で具体的に
   - **重要な決定・制約・前提**: なぜその方針にしたかを含め、議論を繰り返さないために残す
   - **関連ファイル**: 変更したファイル / 次に読むべきファイル（パス付き・各 1 行説明）
   - **git 状態**: ブランチ名・未コミット変更の有無・直近コミット（git リポジトリの場合のみ）
   - **落とし穴 / 試して失敗したこと**: 同じ轍を踏まないための注意

3. **出力**
   - 引き継ぎプロンプト本体を **1 つのコードブロック（```）で囲んで** 出力する（丸ごとコピーできるように）
   - 本文は **日本語**。冒頭を次セッションの Claude への宛て文にする（例:「以下の作業を引き継いでください。」）
   - 次セッションで `@` 参照すべきファイルがあれば、プロンプト内に **`@パス` 形式** で明記する（Claude がそのまま読み込めるように）
   - コードブロックの **前後に短い案内** を添える（コピーして次セッション冒頭に貼る旨）
   - コンテキスト圧縮が目的のため **冗長にしない**。1〜2 画面に収め、情報の薄い飾り文は入れない

### 注意

- **画面表示のみ**。ファイルへの書き出しは行わない（ユーザーが明示的に求めた場合を除く）
- 機密情報（トークン・認証情報・パスワード・接続文字列）はプロンプトに含めない
- 「やったつもり」を書かない。未完了・未検証の項目は正直にその旨を記す
