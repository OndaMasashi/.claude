# 各プロジェクトの memory を非公開リポジトリへ毎日退避する

## 対象

- `scripts/memory-backup.sh`（新規。退避の本体）
- `hooks/dependabot-alerts.sh`（退避が 3 日以上成功していなければ起動時に知らせる判定を追加）
- リポジトリ外: 非公開リポジトリ `claude-memory-backup` と手元の clone（`~/claude-memory-backup`）、タスクスケジューラ「ClaudeMemoryBackup」（毎日 12:00、PC が切れていたら次の起動時）
- 2つのプロジェクトの memory 3ファイル（平文のパスワード3箇所と API トークン1件を外した。トークンはそのプロジェクトの `.env` へ移した）

## 変更内容

- `~/.claude/projects/*/memory/` だけを clone の `projects/` に丸ごと写し、変更があれば commit、毎回 push する。会話ログ（`*.jsonl`、`projects/` の約 11GB の大半）は写さない。
- 写す前に、送り先が非公開の GitHub リポジトリであることと、memory フォルダが1件以上あることを確かめる。どちらかを満たさなければ止まる。
- API キー・トークンの形をした文字列があれば commit せずに止まる（OpenAI・Anthropic・Stripe・GitHub・AWS・Google・Slack・JWT・秘密鍵）。検査そのものが失敗したときも止まる。
- パイプの途中の失敗も拾う（`pipefail`）。`-` で始まるフォルダ名を tar がオプションと読まないよう `./` を付ける。認証が切れていても入力待ちにならず、すぐ失敗する。
- 成功したら `~/.claude/cache/memory-backup/last-success` に時刻を書く。起動時フックは、この記録が 3 日以上古い・無い・壊れているときだけ知らせる。フックを新しく足すと `settings.json` の変更が要るため（許可の確認で止められた）、既存の Dependabot フックに判定を足した。外部コマンドは使っていない。

## 理由

memory（63 プロジェクト・約 1,380 ファイル・約 9MB）は PC にしか無く、PC が壊れると失われる。`.claude` リポジトリは公開設定で、memory にはメールアドレス・顧客の業務・人事評価の経緯などが含まれるため、別の非公開リポジトリにした。会話ログは GitHub の容量の目安（1GB）を大きく超え、貼り付けた機密もそのまま残るため対象外にした。

最初の push の前に memory を調べ、実物のパスワードが3箇所に平文で書かれていたので伏せた（同じ値がそのプロジェクトの設定ファイルにあることを確かめてから消した）。最初の検査は「password: 値」の形しか見ておらず、文中に値だけ書かれた2箇所は見落としかけた。

さらに、push の後のセキュリティレビューで、API トークン（JWT 形式）1件が memory に平文で書かれたまま退避先へ送られていたと分かった。当初の検査は決まった形の API キーしか見ておらず、JWT を拾えなかった。トークンを memory から外し、退避先の履歴を作り直した（README だけの commit に戻して強制 push し、改めて退避）。なお、このトークンは元のプロジェクトのソースファイルと、その非公開リポジトリの過去の commit にも直接書かれていた。

`/refine` では、正確性のバグ 15 件（緊急 1・通常 6・様子見 5・設計の提案 2・対応済み 1）と、セキュリティの指摘 11 件（重複を除いた新規は様子見 4）が見つかった。緊急と通常の 7 件を直した。

## 検証

- 送る範囲: 1,384 ファイルを commit して push。memory 以外のファイルが含まれていないことを `git ls-files` で確認した。
- GitHub の API で、送り先の最新 commit と非公開設定を確認した。
- 定期実行: タスクスケジューラから手動で起動して結果コード 0 を確認した。翌日 12:00 の定期実行も成功していた。
- 直したスクリプトを実際に1回動かし、非公開の確認・commit・push まで通ることを確認した。
- 新しい秘密情報の検査: 今の memory では何も拾わない（誤検知なし）。外す前のトークン入りのファイルは拾うことを確認した。
- 起動時フック: `HOME` を一時フォルダに向けて5通りで試した。「今日成功」「先頭ゼロ付きの昨日」は何も出さない。「5日前」「記録なし」「壊れている」では通知を出す。
- 履歴の作り直し:
  - 手元の古い commit は消え、全履歴にトークンが無いことを `git log --all -S` で確認した。
  - GitHub 側では、消した2つの commit をまだ SHA 指定で開ける。参照されなくなった commit を GitHub がすぐには消さないため。

## 残作業

- GitHub に残る、消した2つの commit の扱い。完全に消すには、リポジトリを作り直す（`gh auth refresh -s delete_repo` が要る）か、GitHub Support に依頼する。
- 元のプロジェクトのソースファイルと、そのリポジトリの履歴に残るトークンの扱い。発行元で作り直すのが確実。
- `/refine` の様子見の指摘は今回は直していない。
  - memory が大幅に減っても止まらない
  - 1件の秘密情報で全プロジェクトの退避が止まる
  - 無人の Claude 実行にも通知文が混ざりうる（Dependabot フックの停止スイッチで止まるようにはなった）
  - 連休明けに誤って通知が出る
  - 消す場所の確かめ方が弱い
  - リンク経由で別のファイルが混ざりうる
  - 同時実行への備えが無い
- 秘密情報の検査は決まった形しか拾えない。パスワードやトークンの値は memory に書かない運用で防ぐ。
