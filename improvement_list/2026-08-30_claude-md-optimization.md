## 理由

公式ドキュメントは「2つの規則が矛盾すると Claude はどちらかを恣意的に選ぶ」と明記しており、同じ規則が別の言い回しで散っている状態は実害になる。また `tech-versions.md` は「訓練時の知識で最新版を判断するな」という事故防止ルールの本体でありながら、実測ではほとんど開かれていなかった。

### 判断の根拠にした実測（全2,192セッションの記録を横断・2026-08-30）

| 外部化ファイル | サイズ | 開かれた回数 |
| :--- | ---: | ---: |

| ng-words-ja.md | 7.9KB | 12 |
| orchestration-guide.md | 10.0KB | 16 |
| skills-catalog.md | 14.0KB | 16 |
| model-dev-playbook.md | 18.6KB | 0 |

FW 名に触れた 2,018 セッションのうち `tech-versions.md` を開いたのは14件。**この分母は過大**（単なる言及を含む）なので遵守率としては読めない。HYPOTHESIS 止まりだが、1.5KB のファイルを外部化しておく理由としては弱いと判断した。

公式仕様として確認した前提: **`@` 取り込みは起動時に展開されるためコンテキストは減らない**。減らせるのは Read を遅らせたときだけ。したがって 10KB 超の3ファイルは Read のまま維持するのが正しく、`@` 化していない。

- **見出し構成の突き合わせ**: CLAUDE.md と global.md の差が想定した4点だけであることを確認。
- CRLF 0件・BOM なし（`core.autocrlf=true` のため混入すると全行が差分になる）。

## 残作業

1. **200行の推奨を超えている**: 公式は「CLAUDE.md は200行未満を目標」としているが、実効 207行になった。元が197行で余白がなく、`@tech-versions.md`（ユーザー決定）と重複統合のための新設節を足した分。**これ以上詰めるにはルール本体を削る必要があり、今回の前提（内容は薄めない）と衝突する**ため、超過を受け入れた。次にルールを足すときは、どれかを外部化するか統合する判断が要る。
2. **settings.json の `Write(...)` deny ルールが機能していない**: 別セッション起動時の警告で判明。「`Write(path)` はファイル権限チェックに一致しない。すべてのファイル編集ツールを覆うのは `Edit(path)`」とのこと。**保護自体は `Edit(...)` の行が効いているので破れていない**が、`Write(...)` の4行は無効で、起動のたびに警告を出している。削除すればノイズが消える。
3. `model-dev-playbook.md` が0回だった件は、記述を現状維持のうえ HTML コメントに実測を残した。次に新規 ML 開発を始めたときに実際に発火するかを見て、しなければトリガー文言かスキル化を検討する。
